## 3. Найденные и исправленные дефекты

В рамках работы были найдены и исправлены **4 дефекта**, заложенных в `hw1-broken`.

### Дефект 1. Имя модели захардкожено в коде

**В чём был дефект:**

В трёх файлах проекта имя модели было прописано жёсткой строкой:
- `src/model.py` — `name = "Qwen/Qwen3-0.6B"` внутри функции `load_model`
- `src/generate.py` — `print(f"Модель: Qwen/Qwen3-0.6B")`
- `src/bench.py` — `"model": "Qwen/Qwen3-0.6B"` внутри словаря `report`

**Как проявлялся:**

При изменении `params.yaml` (например, замена модели на `SmolLM2-135M-Instruct`) код продолжал загружать `Qwen/Qwen3-0.6B`. Это противоречило главному правилу курса — конфигурация должна храниться только в `params.yaml`.

**Как исправлено:**

- В `src/model.py` строка заменена на `name = params["model"]["name"]`
- В `src/generate.py` — `print(f"Модель: {params['model']['name']}")`
- В `src/bench.py` — `"model": params["model"]["name"]`

### Дефект 2. Зависимости без версий

**В чём был дефект:**

В файле `pyproject.toml` в разделе `dependencies` были указаны только имена пакетов без указания версий:

dependencies = [
    "torch",
    "transformers",
    "accelerate",
    "numpy",
    "pyyaml",
]

**Как проявлялся:**

При установке на разных машинах могла установиться разная версия одной и той же библиотеки. Это приводило к тому, что код, работающий у одного студента, мог сломаться у другого или в CI (Continuous Integration) из-за несовместимости API между версиями. На девятой неделе курса, когда проект разрастается, такая проблема становится критической.

**Как исправлено:**

В `pyproject.toml` добавлены конкретные версии (с оператором `>=` для совместимости):

dependencies = [
    "torch>=2.1.0",
    "transformers>=4.36.0",
    "accelerate>=0.25.0",
    "numpy>=1.26.0",
    "pyyaml>=6.0",
]

После этого выполнена команда `uv sync`, которая обновила файл `uv.lock`, зафиксировав точные версии всех транзитивных зависимостей.

### Дефект 3. Неправильный замер скорости в bench.py

**В чём был дефект:**

В `src/bench.py` использовался один таймер `t0`, который засекался до загрузки модели и использовался для вычисления скорости генерации. Таким образом, в `tokens/sec` включалось время загрузки модели, что делало результат бессмысленным — он был искусственно занижен и почти не зависел от длины ответа.

**Как проявлялся:**

При запуске `make bench` скорость генерации оказывалась неправдоподобно малой (например, 1-2 токена/сек), так как в расчёт попадало время загрузки модели (~3.5 сек), которое никак не связано с генерацией.

**Как исправлено:**

Структура `src/bench.py` перестроена:

1. **Отдельный замер загрузки**: `t_load_start` засекается до загрузки модели, `load_time` вычисляется сразу после загрузки.
2. **Добавлен прогрев (warmup)**: перед замерами выполняется один прогон генерации, который не учитывается в финальных расчётах. Прогрев необходим для того, чтобы модель выделила память, прогрела кэши и скомпилировала ядра (это особенно актуально для CPU).
3. **Замер скорости отдельно для каждой итерации**: теперь таймер `t_gen_start` засекается непосредственно перед генерацией на каждом из трёх измерительных запусков, а `elapsed` считается только как время генерации.

### Дефект 4. Недетерминированность генерации

**В чём был дефект:**

В `params.yaml` в разделе `generate` было указано `temperature: 0.7`, что включало сэмплинг (случайный выбор токенов). При этом в `src/generate.py` не был вызван `set_seed()`, хотя в `src/model.py` такая функция была написана.

**Как проявлялся:**

Два последовательных запуска `make generate` давали разный текст, хотя задание требовало детерминированности (воспроизводимости) при `temperature = 0`. При `temperature = 0` модель должна была всегда выбирать самый вероятный токен, но из-за отсутствия фиксации seed и включённого сэмплинга этого не происходило.

**Как исправлено:**

- В `params.yaml` параметр `temperature` изменён с `0.7` на `0.0`
- В `src/generate.py` добавлен вызов `set_seed(params["generate"]["seed"])` перед загрузкой модели
- Проверено: два запуска `make generate` дают идентичный вывод (проверялось через `fc out1.txt out2.txt`, файлы оказались идентичными)
